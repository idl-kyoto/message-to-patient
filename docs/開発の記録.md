# 開発の記録

Built with Claude: Japan 2026 の参加者である医師と、Claudeによる、開発の記録です。Claudeが下書きし、医師が確認しました。失敗したところや、やり直したところも、そのまま書きます。

## この記録の使い方

- 何を、誰が決めたか（医師が決めたこと、Claudeが行ったこと）を、分けて書きます
- うまくいかなかったことと、直したことを書きます
- 確認できていないことを書きます

## 作り方の原則

- 医学の内容は、医師が決めます。Claudeは、補いません
- Claudeは、医師の話を聞いて、質問して、整理します。聞くことが先で、埋めることはしません
- 文は、医師の言葉です。文献は、医師が判断するための材料にとどめます
- アプリは、実行時に、Claudeを呼びません。外部通信もありません
- 作業の前に、日時つきのバックアップを作ります。公開（push）は、医師が、自分で行います
- コード（Claude Code）への指示書には、必ず、4つを書きます（変更の範囲、範囲外で見つけたときの扱い、連続して見つけたときの継続条件、完了の条件）。仕様の判断は、勝手にせず、戻します

## 経過

### 2026年11月2日：土台づくりと、文章の素材

- 公開リポジトリを作りました。コミットの記録に、個人情報が出ない設定にしました
- READMEの最初の版を、医師の言葉に直して、書きました
- 医師のサイトの病気辞典の文章を、素材として使うことにしました。Claudeが、サイトを自動で読もうとしたところ、サイト側に断られました。Claudeは、迂回せず、医師に、ページの本文を貼ってもらいました
- 貼ってもらった4ページ（足首の捻挫、腰部脊柱管狭窄症、ハムストリング損傷、骨粗鬆症）から、Claudeが、文章モジュールの下書きを作りました。そのあと、元のページと突き合わせて、食い違いを点検しました。3点が見つかりました
  - 腰部脊柱管狭窄症の混合型の説明が、ページにあるのに、下書きで「説明なし」になっていた
  - 腰部脊柱管狭窄症の歩ける距離の数字が、ページと違っていた（ページにない「数百メートル」を、入れていた）
  - 骨粗鬆症の背筋強化は、ページでは「閉経後女性」の運動だった。下書きは、この条件が抜けていた
- これは、「ページにない内容を足さない」という原則を、Claude自身が、破りかけた例です。突き合わせで見つけて、直す案を出しました

### 2026年11月3日 午前：1階を作る（v1〜v1.4）

設計を、医師と相談して、決めました。

- 構造は、疾患 → 変数 → 選択肢 → 文章モジュールの文。データは、疾患ごとの外部のJSONです
- 変数の型は3つです（1つだけ選ぶ、複数選べる、必ず出す）。「該当なし」は、何も印刷しません
- 書面は3層です。毎回必ず出る「外せない注意書き」（本文は編集も削除もできません。連絡先だけ、医療機関ごとに設定します）、選んだ文章モジュール、患者さんごとの特別指示（保存しません）
- 点検は、アプリ内のルールで行います（選び忘れ、外せない注意書きの欠落、連絡先の未設定）
- 当初は、実行時にClaudeが点検する案もありました。実装では、実行時にClaudeを呼ばない形にしました。READMEは、実装に合わせて、直しました
- 空欄の文の扱いは、医師の判断で、変えました。当初は、空欄だと印刷を止める設計でした。医師が、「チェックを入れたことが、意思表示になる」と判断したので、空欄でも止めず、選択肢の名前を、そのまま印刷するようにしました

実装は、Claude Codeが行い、コミットしました。

- v1：足首のデータ、書面の組み立て、点検、承認後の印刷
- 連絡先が未設定のときは、印刷できないようにしました
- 文が空欄でも、印刷を止めず、選択肢の名前を印刷するようにしました
- 印刷の見た目を整えました（題名、印刷日、見出し、枠）
- 書面を、カード型にして、A4の1枚に収めました

### 2026年11月3日 午後：印刷の確認と、表記の統一

- 印刷のプレビューが、2枚になる件を、医師が、Safariで調べました。「ヘッダとフッタをプリント」を外し、「用紙サイズに合わせる」を選ぶと、1枚に収まりました
- 「両面印刷の設定が原因」と考えましたが、違いました。医師が、両面印刷をオフにしても、2枚のままでした。実際は、縦の長さが、ぎりぎりでした
- 文の表記ゆれを、医師が指摘して、直しました。「痛みの範囲で、普通に歩いて構いません」を、「強い痛みが出ない範囲で、ゆっくり歩いて構いません」に統一しました。「普通に」は、個人差があるので、書かない、という医師の判断でした
- READMEは、第1版と第2版に分けて、残しました。第2版は、実装に合わせて直したものです（実行時にClaudeが点検する、という記述を直しました）

### 2026年11月3日 午後：空のアプリと、2階

- 足首のアプリは、そのまま残して、中身を空にした、別のコピー（空のアプリ）を作りました。公開先（リモート）は、ありません。間違って公開しないためです
- 2階とは、医師が、空のアプリに入力していって、書面を出力させるための入れ物です。最初は、「Claudeとの対話の画面」だと考えていました。医師の意図は、「スプレッドシートのように、縦にも横にも増やせるアプリ」でした

### 2026年11月3日 午後：2つ目の疾患（骨粗鬆症の運動処方箋）

2階の仕組みを使って、2つ目の疾患を作りました。相談の開始から、データの下書きまで、約1時間でした。

- 日本骨粗鬆症学会などのガイドライン（2025年版）の運動療法の記載は、2ページほどでした。具体的な処方は、書かれていませんでした。医師に、紙面の写真で、見せてもらいました。Claudeは、複写が禁止されたPDFを、回避して読むことはしませんでした
- Claudeが、文献を調べました。「膝を痛めずに、骨を強くする筋トレ」を直接示した研究は、見つかりませんでした。水中運動は、何もしないよりは、骨に良さそうですが、陸上運動より、効果は小さいという結果でした。結果は、医師の判断の材料としてだけ、使いました
- 医師の診療経験で、決めました
  - 膝が悪くて歩けない方は、まず痛みを取る。膝の運動、水中歩行、自転車を、勧める
  - ゆっくり歩ける方は、無理をさせない。膝まわりの筋トレ、太ももを上げて歩く、机に手をついた足踏み
  - 早歩きができる方は、息が軽く弾む速さで、30分
  - 腹筋と背筋は、背骨を曲げない
  - 続けることが、一番大事。最初からハードルを上げず、しんどくない程度に、毎日ちょっとずつ
  - 冒頭に、「悪い流れ」（骨折、転倒、フレイル、寝たきり、寿命への影響）を、医師の言葉で入れる
- 対象は、閉経後の原発性骨粗鬆症が中心です。続発性（ステロイドなど）は、別です。他の病気で運動を制限されている方は、担当医の指示を優先します

### 2026年11月3日 午後：2階の作り直し

- 最初の2階は、マスごとに、入力欄を並べました。骨粗鬆症のデータを読み込むと、表が大きくなりすぎて、人間には使えませんでした。医師の指摘は、「コンピューター的にはわかるかもしれんけど、人間には無理」でした
- 表は、名前だけにして、細かい入力は、選んだマスの下の編集欄で行う形に、作り直しました。5列が、横スクロールなしで、1画面に収まりました
- 保存の仕組みも、説明し直しました。自動保存は、ブラウザの中です。「データを書き出す」で、ファイルになります。書き出し先は、専用のフォルダにしました

## うまくいかなかったことと、直したこと

共同作業の中で起きたことを、共に振り返ります。

- 下書きに、ページにない内容（歩ける距離の数字）が入っていた。元のページとの突き合わせで見つけて、直した
- READMEに、実行時の機能（Claudeが点検する）を書きすぎていた。実装に合わせて直した
- 両面印刷が原因と考えたが、実際は、縦の長さがぎりぎりだった
- 骨粗鬆症の材料は、そろっていると考えたが、実際は、そろっていなかった
- 2階を、Claudeとの対話の画面と考えたが、実際は、スプレッドシートのような入れ物だった
- 医師のサイトは、自動で読めると考えたが、実際は、サイト側に断られていた。医師に、貼ってもらう形が、確実だった
- 単一選択に「該当なし」は作れないと考えたが、実際は、作れた

## 確認の方法

- テスト：node による自動テスト。2階の読み込みと書き出しが、元のデータと完全に同じになること、点検の項目、並べ替え、などを確認した
- 画面：ヘッドレスブラウザと、医師が、Safariで、実際に操作して確認した
- 確認できていないこと：スマホでの2階の操作、他の疾患（骨粗鬆症以外）の2階での作成、書面の実際の診察での使用

## 限界と、今後の課題

- 骨粗鬆症の運動の説明文の一部は、まだ空欄です（空欄のときは、選択肢の名前が、書面に出ます）
- 書面の強調（目立つ枠）は、4番目の中見出しに、決め打ちです。疾患ごとに指定できるようにする課題があります
- 2階は、中見出しの削除ができません（使われなくなったものが、書き出しに残ります）
- 骨を強くする運動の、具体的な根拠は、限られています。書面は、医師の臨床経験をまとめたもので、診療ガイドラインそのものではありません
- 診断、治療の判断は、すべて医師が行います。このツールは、判断をしません
